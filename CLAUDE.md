# Cantonese Learning Games

Static HTML Cantonese lessons and games served with GitHub Pages at https://ssullivan.github.io/learn-cantonese/ (from `main`, repo root). No build step for the site itself; `tools/` scripts generate assets and check the site.

Maintainability and DRY come first: anything two pages or units share belongs in `shared/` (browser) or `tools/` (Node), not in copies. Generated files are never edited by hand; edit their source and regenerate.

## Layout
```
index.html               unit picker
shared/                  used by every page; each file's header comment documents its API
  theme.css              colors (light/dark), fonts, header, pills, buttons, cards, feedback, answer buttons
  core.js                Canto.*: helpers every script uses (zh, jyutping, pick, play, store, picButton, speech)
  audio.js               Speak.play(src|[src], text): MP3s with zh-HK speechSynthesis fallback
  learn.css, learn.js    learn-page engine (Learn.init, word cards, listen quiz)
  game.css, game.js      game engine (Game.init: levels, rounds, timer, score, stars, unlocks)
  tones.js               Tone Detective, usable by any unit (Tones.init)
  pitch.js               pitch tracking + contour charts (Pitch.*); runs in Node too
  sayit.css, sayit.js    Say It Back speaking practice, usable by any unit (SayIt.init)
unit<N>/
  index.html             unit page: a card per learn page / game
  vocab.js               window.VOCAB: every word in the unit (source of truth)
  art.mjs                the unit's SVG drawings, built from tools/svg.mjs parts
  learn.html, lessons.js learn page and its steps
  <game>.html, <game>.js unit games on Game.init (unit1/trolley.*); tones.html and say.html configure the shared ones
  img/<id>.svg           generated by tools/draw.mjs
  audio/<id>.mp3         generated by tools/tts.mjs (+ manifest.json)
tools/
  site.mjs               shared helpers for the scripts (unitDirs, loadVocab, loadArt)
  svg.mjs                shared drawing parts (svg, steamer, plate)
  draw.mjs               art.mjs → img/*.svg
  tts.mjs                vocab.js → audio/*.mp3 (Azure Speech)
  check.mjs              site checks; --fix writes cache stamps; runs tools/*.test.mjs
  pitch.test.mjs         pitch.js on synthetic voices with known pitch
```

## Words, audio and pictures
- Every word lives once, in `unit<N>/vocab.js`: `{ id, hanzi, jyutping, english, note?, img?, measure?, say?, ssml? }`. `id` names its files. `img: false` means no picture.
- Derive, don't copy: phrases built from words (like unit 1's `portions`, 一籠蝦餃) are computed at the bottom of `vocab.js`, and get audio like any entry.
- Measure words: a dish's `measure` must match its picture (籠 ↔ `steamer()`, 碟 ↔ `plate()`); check.mjs enforces it.
- Jyutping uses tone numbers on every syllable (`haa1 gaau2`). Double-check sandhi/changed tones (腸粉 coeng2, 燒賣 maai2) and words with several readings.
- Use colloquial Cantonese (佢, 係, 唔, 咗), not Mandarin or written-Chinese forms.
- Audio: `node tools/tts.mjs [unitN] [--only id,id] [--force]`. It only regenerates entries whose text or voice changed. Credentials come from `~/.config/learning-cantonese/config.env` (`AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`); never commit them. If a word is misread, add an `ssml` override. A person has to listen to new clips; nobody else can check pronunciation.
- Pictures: add a drawing to `unit<N>/art.mjs`, run `node tools/draw.mjs`. Reuse or extend the parts in `tools/svg.mjs` instead of copying markup. Keep the 128×128 flat style, fixed colors, transparent background, and a `<title>`. Render and look at new drawings before committing.

## Pages
- Pages load `shared/` with `../shared/...` and use relative links only (the site is served under `/learn-cantonese/`, not `/`).
- Local CSS and JS are loaded with a `?v=<hash>` cache stamp; `node tools/check.mjs --fix` writes them. Never edit a stamp by hand.
- Learn pages run on `shared/learn.js`; `unit1/learn.html` + `lessons.js` is the template. Games run on `shared/game.js`; `unit1/trolley.*` is the template. Put reusable UI in `shared/`, not in a unit's script.
- Script order: `core.js`, `audio.js`, then `learn.js` or `game.js`, then the unit's `vocab.js` and page script.
- No emoji in the UI (they break on systems without an emoji font); use text, ▶, ★, or a Chinese character badge (`Canto.speech`).
- Game pages and learn pages link back to their unit page with `href="../"` ("← Unit N").
- When adding a learn page or game, add its card to `unit<N>/index.html` (turning a "Coming soon" card into a real one).
- When adding a unit, create `unit<N>/` like `unit1/`, add a card to the root `index.html` in unit order, and update its "Units …" eyebrow.
- `localStorage` is shared by the whole site, so keys must be unique: `u<N>-learn`, `u<N>-<game>`.
- `.nojekyll` disables Jekyll processing so files are served as-is.
- Avoid gendered pronouns for named people in lessons; reword instead.

## Checking a change
1. `node tools/check.mjs --fix`: must print "All checks passed" (links, stamps, JS syntax, vocab ↔ audio ↔ art, SVGs up to date, tests).
   Tests must be able to fail: after writing one, break the code on purpose and confirm check.mjs reports it.
2. Serve locally (`python3 -m http.server`) and try the page at phone (390px) and desktop widths, in light and dark mode: no horizontal scroll, all audio plays, quizzes and game levels complete, and timers, stars and unlocks work.
